DEVELOPER PLATFORM

CenAI API
architecture preview.

The API platform is planned as a secure, provider-independent gateway. These endpoint shapes are proposals and are not live service URLs.

CHAT

POST /v1/chat/completions

Streaming and non-streaming chat with explicit model selection or automatic routing.

MODELS

GET /v1/models

Discover enabled models, capabilities, and provider availability.

EMBEDDINGS

POST /v1/embeddings

Create vectors for approved knowledge and retrieval workflows.

AGENTS

POST /v1/agents/runs

Start bounded agent jobs with scoped tools and approval checkpoints.

USAGE

GET /v1/usage

Inspect quota, estimated cost, and usage history for the authenticated account.

WEBHOOKS

POST /v1/webhooks

Register signed event delivery for supported developer workflows.

Required security contract

  • Per-user API keys, hashed at rest and shown only once.
  • Scoped permissions, rotation, revocation, and audit events.
  • Server-side provider credentials; never expose master keys to clients.
  • Rate limits, quota enforcement, request-size limits, and abuse detection.
  • Explicit retention policy and privacy controls.
  • Versioned schemas, error formats, idempotency, and documented deprecations.

No API key generation, billing, or provider calls are enabled by this static preview. Those require the authenticated backend, database, payment configuration, and operational secrets.

DEVELOPER PLATFORM

CenAI API v1

Initial public endpoints for registered API keys. Model listing and usage reporting are available; chat completions and paid quotas are not yet enabled.

Authentication

X-API-Key: cai_live_YOUR_KEY

Available endpoints

GET /api/v1/models — lists enabled public models.

GET /api/v1/usage — returns your aggregate usage for the last 30 days.

API keys are created in the administrator control panel and are displayed only once. The public API is disabled until the owner enables api.public.enabled after reviewing the launch settings.
