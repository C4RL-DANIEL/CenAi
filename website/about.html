ABOUT CENAI

AI should help you do the work—not take control of it.

CenAI is an independent software project exploring a more organized way to work with artificial intelligence: bring models, projects, knowledge and carefully permissioned actions into one workspace.

Why CenAI exists

AI tools are useful, but work often gets scattered. A conversation lives in one service, a project brief in another, files somewhere else, and automations in a separate dashboard. Moving between them makes it harder to keep context and understand what an AI system is doing.

CenAI is being built around a simple idea: the workspace should connect the parts of the process while keeping important decisions visible to the person using it.

What the workspace is designed to bring together

  • Model choice: connect supported providers and choose a model based on the task, capability, speed, cost and data requirements.
  • Project context: keep briefs, reference files, notes and work history organized around a project.
  • Permissioned agents: prepare plans and proposed actions, with approval checkpoints for sensitive operations.
  • Android access: bring compatible workspace features to a mobile device, with offline behavior depending on the feature and model.
  • Developer foundations: build toward documented APIs, integrations, usage controls and observable services.

How we approach product development

We prefer clear status over impressive claims. A roadmap item is not the same as a shipped feature, a preview is not a production guarantee, and an AI response is not automatically correct. Public product pages should distinguish what is available today from what is still being developed.

We also believe automation should be understandable. An agent should show what it intends to do, use only the permissions it needs, and pause when an action could affect an account, publish information, spend money or change important data.

What CenAI is not

CenAI is not a promise that one model is best for every task, that AI outputs are always accurate, or that every planned integration is already available. Provider availability, model capabilities, device support and feature access can change. Users should review important outputs and verify actions before relying on them.
