QUALITY & VERIFICATION

How to check an AI answer before relying on it

A repeatable verification process for AI-generated facts, calculations, code and recommendations, including the extra checks needed for high-impact decisions.

By CenAIUpdated 17 November 20267 min read
In this guide
  • Start with the risk
  • Check claims against sources
  • Verify calculations and code
  • Review recommendations
  • Keep a verification trail

Start with the risk of being wrong

Not every AI response needs the same level of review. A brainstorming list can be judged for usefulness. A command that deletes files, a medical explanation, a tax calculation or a payment instruction needs stronger verification. Before relying on an answer, ask what would happen if it were wrong, incomplete or misunderstood.

Use a higher review standard when the answer affects money, safety, health, legal rights, access to accounts, production systems or another person's data. In these situations, an AI response should support a qualified decision-maker, not replace one.

Check factual claims against primary sources

Ask the model to separate facts from assumptions and to identify the source for each important claim. Then open the source yourself. Prefer official documentation, laws, product specifications, original research and direct records over summaries that repeat one another.

Check whether the source actually supports the claim. A link to a product page does not prove a feature is available in your country or plan. A search result snippet does not prove that the full article says what the model claims. Verify the publication date, version and scope.

When no source is available, label the statement as unverified. Ask what evidence would change the conclusion. Do not turn a plausible-sounding explanation into a fact simply because it is written confidently.

Verify calculations and code independently

For calculations, reproduce the result with a calculator, spreadsheet or a short independent script. Check units, rounding, assumptions and edge cases. For a financial estimate, confirm whether taxes, fees, recurring charges or currency conversion were included.

For code, read the patch, inspect dependencies, run tests and review the effect on existing behavior. A successful build does not prove that the feature works correctly. Test failure paths, invalid input, permission boundaries and the environment in which the code will run.

For data extraction, compare a sample of outputs to the original records. Check whether missing values, ambiguous dates, duplicate rows and unusual formats were handled correctly.

Review recommendations and assumptions

Ask the model to list its assumptions, alternatives, trade-offs and confidence limits. Then challenge the most important assumption. If the recommendation depends on current pricing, availability, law or provider policy, check a current authoritative source. If it depends on your own situation, confirm the input data rather than allowing the model to fill gaps with guesses.

A useful second pass is to ask for the strongest reason the recommendation might be wrong. This does not guarantee correctness, but it can expose missing constraints and one-sided reasoning.

Quick review checklist

What is the claim? What source supports it? Is the source current? What assumptions were made? Can I reproduce the calculation or test the code? What happens if this answer is wrong?

Keep a verification trail

For consequential work, record the source, date checked, model and version where known, test performed, reviewer and final decision. Keep the original input separate from the AI-generated summary. This makes it easier to investigate an error and update the decision when facts change.

Do not share confidential source material with a second AI provider merely to get another opinion unless that provider is approved to receive it. Independent verification can be done with trusted documentation, a local tool or a qualified human reviewer.

Key takeaway

AI can speed up research and drafting, but responsibility for consequential decisions remains with the person or organization using the result. Match review effort to risk, check primary sources, reproduce calculations, test code and record how important conclusions were verified.

For a broader framework for managing AI-related risk, see the NIST AI Risk Management Framework.
